# Cut the oversupply, then verify every receipt

The research notes contain about **560 candidate timeline records plus 52 people cards**, so building the ~350-entry "Unhyped" dataset is mostly a matter of cutting, not finding more. The recommended split is **10 prologue, 35 for 1943–1979, 45 for 1980–2011, 70 for 2012–2021, 170 for 2022–Sep 2026 and 20 projections**. That split already adds up to 350, so people, Claim-vs-Reality pairs and "Still alive" follow-ups should live in linked overlay tables rather than count as timeline entries. The biggest single trimming lever is to fold point releases (Opus 4.1/4.7/4.8, GPT-5.1/5.2/5.4, Gemini 3.x Flash, Midjourney V4–V8, ChatGPT feature drops) into a `major_updates` array on each family entry, which keeps coverage without using up slots. About 59 claim pairs pass the verbatim test. Only about half have been checked against a primary or directly-quoting source. Every quote taken from a talk or video (Hinton 2016, Musk 2016/2019, Huang 2024, Amodei at CFR and Davos) still needs the recording checked, and several famous lines (Minsky in LIFE 1970, Musk on 10,000 Optimus robots, Amodei's bloodbath framing) must be dropped or replaced. The user's source timeline is mostly accurate. Its errors are same-week launches merged into one date (Claude Opus 4.6 shipped Feb 5, 2026, not Feb 17) and stale statuses (Roo Code, Flowise and Hugging Face TGI are dead). It is also missing Claude Cowork, Claude Sonnet 5, the Sora shutdown and Hermes Agent. For credibility, the ledger has to include bold claims that came true (AlphaFold, IMO gold, Salesforce's support cuts) and dismissals of AI that were wrong (Chegg). The two largest integrity risks for the build are 2026 events that have only one source and GitHub star counts at a time when a peer-reviewed study found about 6 million suspected fake stars.

## Five rules turn 560 candidates into a defensible 350

The six note files were written by different researchers, and they disagree in ways that will corrupt the build if not fixed first. **Field names differ** across files: file 01 uses `primary_segment`/`stack_layer`/`source_url`, file 05 uses `seg`/`layer`/`desc`/`src`, and file 02 uses pipe-delimited lines. **Era assignment follows two incompatible rules.** File 01 assigns era by capability regardless of date, so SNARC (1951) is era 3 and Hubel & Wiesel (1962) is era 4. File 05 uses fixed chronological cutoffs: era 5 "Machines write" runs Jan 2022–Aug 2024, era 6 "reason & use tools" starts with o1-preview on Sep 12, 2024, and era 7 "act & create across media" starts with ChatGPT agent in Jul 2025. As a result the same artifact gets different eras: PyTorch is era 3 in file 02 and era 4 in file 03, Whisper is era 4 in file 03 and era 5 in file 05, and latent diffusion is era 4 while Stable Diffusion is era 5. The notes define eras 0–7 (Tools extend the hand, Machines follow logic, follow rules, learn patterns, see & hear, write, reason & use tools, act & create across media) but **never define era 8**. Reserve it for projections and have the editor name it.

The first rule is to **normalize to one schema before trimming**. The required fields stay (id, title, date, type, era, primary/secondary segment, stack layer, creators, description, edges, source_url). Add `date_precision` (day/month/year/range), `verification` (live-fetched, canonical-unfetched, single-source, †), `capability_note`, `major_updates[]`, `status_as_of` (active, pivoted, archived, shut down), `stars` plus `stars_as_of` for repos, `hero` and `claim_ids[]`. The second rule is **one era rule, written down**: use capability for pre-2022 entries and file 05's reproducible chronological cutoffs for 2022 onward, and fix the conflicts listed above. The third rule is **type hygiene**. Babbage and Leibniz are typed "Person" in file 01 and should become Product/Paper. The TPU is typed "Model". "Open-source" and "Open-source repo", and "Major" and "Major update", need merging. The fourth rule is **dedupe across files**. These appear in two or more files: `google-brain-2011`/`google-cat-paper`, PyTorch (with conflicting dates, Sep 2016 public beta vs Jan 2017 public release), JAX, HF Transformers, The Pile/EleutherAI, Whisper, Stable Diffusion/latent diffusion, FlashAttention, Mamba, gpt-oss, DeepSeek-R1 (paper and model), LLaMA, MCP/mcp-servers and LangChain. The fifth rule is **overlay, don't count**. People (52 cards, plus Daniel Kokotajlo, whom file 06 recommends adding), Claim-vs-Reality pairs and "Still alive" follow-ups attach to entry ids through `claim_ids` and `creators` edges. The claims file already carries a `related_entry` key for this.

Promote either one only after the dust settles. Balance also matters within heroes. Anthropic products fill 3 of the 8 hero slots for 2022–2026, so consider replacing claude-cowork with the IMO-gold or DeepSeek-R1 cluster if the team wants to avoid a vendor-tilt critique.

## Conclusion

Curating these notes shows that the "unhyped" pattern holds most clearly for **timelines, not directions**. Hinton, Musk, Amodei, Zuckerberg and Mostaque mostly got the direction of travel right and the dates badly wrong. Dartmouth, Simon, Minsky and the 1958 perceptron coverage fit the same shape: a real narrow demo, a fixed-horizon forecast, an official review, then a funding cut. A dataset that scores claims by how far the dates missed, and that shows the bold claims that landed (AlphaFold, IMO gold, coding-agent revenue) and the dismissals that failed (Chegg), will be much harder to wave away than a list of gotchas. The "Still alive" table adds a finding the source file did not have: AI has hurt businesses that sell answers (Stack Overflow Q&A, Chegg) far more than businesses that own workflows (Adobe, Salesforce, Google), whose revenues grew even as their stock multiples fell.

The main risk to the build is not missing coverage. It is a small number of weakly sourced 2026 records that would undermine an anti-hype brand if they turned out to be wrong. These are the OpenAI agent cyber incidents, the Meta Muse launch details, the Kilo and Groq deals, and the star-velocity records. Clearing the P0 quote checks and the P1 single-source events before building any visual layer is the step that decides whether "Unhyped" is itself credible.
